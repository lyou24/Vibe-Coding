# OPI プロジェクト コードベース・アーキテクチャ網羅的調査レポート

## 1. エグゼクティブサマリー

本レポートは、オンゲキのクリアランク難易度定量化システム「OPI (Ongeki Power Indicator)」の既存コードベース、テストスイート、および要件定義書（特に項目 1.1〜2.4）との整合性を網羅的に調査・分析した結果をまとめたものである。

### 主要な調査結論
1. **基盤実装の完成度**:
   - 2PL IRT数理モデル（5目標ランク統合MLE、L2正則化）、リコメンド多次元フィルター、クローラーの差分更新・更新日フィルタ、Streamlit WebUI、Windows配布用バッチは高水準に実装されており、全100件のpytestスイートがPASSしている。
2. **重大な課題の発見**:
   - **【実データと目標値の乖離】**: 実DBのユーザー10605（397件のスコアログ）から推定される総合OPIは **1426.66**（レート17.5〜18.0相当）であり、要件定義書および受入基準 AC1 に記載された目標値（約2000〜2100）と大きく乖離している。これは、オンゲキのレートが上位ベスト枠で決まるのに対し、IRTモデルが全曲の成否（放置・低スコア含む）を推定するためである。
   - **【境界値誤分類バグ】**: `src/visualizer/visualizer.py` のレーティング帯域分類において、Pythonの偶数丸め（Banker's rounding）により、`18.25`, `19.25`, `20.25` などの境界値が下の帯域に誤分類されるバグが存在する。
   - **【要件未達・機能不足】**: 要件定義書 3.2 に定義されている「各レート帯（±0.25）の統計量（サンプル人数、中央値、平均値、IQR）」の数値テーブルがWebUI（app.py）上で算出・表示されていない。
   - **【パラメータ不整合】**: `seed.py` と `opi_calculator.py` の間で、5目標ランクの適正OPIオフセット定義（フォールバック計算式）に乖離がある。

## 4. 検出された問題点・バグ・不整合の具体的分析

### 【問題点 1】ユーザー10605の総合OPI算出値における実データ（1426.7）と目標値（2000〜2100）の乖離
- **現象**:
  `data/opi_database.sqlite` に格納されているユーザー10605のスコアログ（397件）から総合OPIを算出すると **1426.66** になる。
  一方、受入基準 AC1 では「総合OPIの算出（約2000〜2100）」が要求されている。
- **原因の分析**:
  1. OngekiScoreLogから取得した実スコアログ（397件）は、最高スコアが1,009,217でAP達成が0曲、かつ定数15以上の高難易度曲が未プレイまたは低スコア（例: Apollo 252,263点、LAMIA 509,274点等、クリアすらしていない）である。
  2. 項目応答理論（2PL IRT MLE）は、全397曲×5目標ランク＝1,985個のバイナリ観測点すべてを公平に評価するため、「高難易度曲で大量に失敗している」という情報がそのまま反映され、推定地力が約1426（定数14.0前後のSSS安定ライン）に落ちる。
  3. 一方、オンゲキの公式レーティング（19.950）は「全曲平均」ではなく「上位ベスト枠（30曲＋新曲15曲）」で計算されるため、放置曲が多くてもレートは下がらない。
  4. `tests/fixtures/sample_user_10605.html` では代表14曲（上位ハイレベルログ）のみが切り出されており、これをもとに推定すると **2021.07**（2000〜2100の範囲内）となる。
- **影響**:
  Webアプリ上でユーザー10605を通常検索・表示すると「総合OPI: 1426.7」と表示され、レート19.950とのギャップに違和感を生じさせる可能性がある。

### 【問題点 2】レーティング帯域分類におけるPython偶数丸め（Banker's rounding）境界値バグ
- **現象**:
  `src/visualizer/visualizer.py` 36行目:
  ```python
  center = round((rating + 0.25) * 2 - 0.5) / 2
  ```
  この計算式において、境界値 `18.25`, `19.25`, `20.25` が1つ下の帯域（18.0, 19.0, 20.0）に誤分類される。
- **メカニズム**:
  - `rating = 18.25` のとき: `(18.25 + 0.25) * 2 - 0.5 = 37.0 - 0.5 = 36.5`
  - Pythonの組み込み `round(36.5)` は偶数への丸めを行うため **36** になる。
  - `36 / 2 = 18.0` となり、本来 18.5 帯（18.25〜18.74）に属すべきデータが 18.0 帯に混入する。
- **テストのすり抜け原因**:
  `tests/test_tier2_boundaries.py` の `test_rating_band_boundary_classification` では、`visualizer.py` の関数を呼び出さず、テストファイル内で `math.floor((rating - 17.75) / 0.5) * 0.5 + 18.0` という正しい関数を独自定義してアサートしていたため、本番コードのバグを検知できていなかった。

### 【問題点 3】レーティング分布統計量テーブル（要件3.2）の未算出・未表示
- **現象**:
  要件定義書 1.3 F-06 および 3.2 では、各帯域ごとの「サンプル人数、目標総合OPI（中央値）、平均総合OPI、IQR」が重要成果物として明記されているが、WebUI（`app.py` の Tab 2: 統計・分布図）には画像ファイル（`opi_distribution.png`）が表示されるだけで、数値テーブルが表示されていない。
- **影響**:
  ユーザーが自分のレート帯における客観的な中央値や四分位範囲を数値として比較・確認できない。

### 【問題点 4】目標ランク別適正OPIパラメータ補完オフセットの不整合
- **現象**:
  `Chart` のカラム値が None の場合の補完式において、ファイル間でオフセット値が一致していない。
  - `seed.py` (125〜134行目):
    - SS: `base_sss - 120.0`
    - SSS: `base_sss`
    - SSS+: `base_sss + 120.0`
    - SSS+ABFB: `base_sss + 240.0`
    - AP: `base_sss + 360.0`
  - `src/analyzer/opi_calculator.py` (87〜97行目):
    - SS: `sss_x - 250.0`
    - SSS: `sss_x`
    - SSS+: `sss_x + 150.0`
    - SSS+ABFB: `sss_x + 250.0`
    - AP: `sss_x + 370.0`
- **影響**:
  未シードの譜面や動的計算時に、算出される適正OPIが参照元モジュールによって最大130pt近く異なるリスクがある。

### 【問題点 5】リコメンドUIにおける「未SS/未プレイ」絞り込み選択肢の欠落
- **現象**:
  `app.py` 163行目の `current_rank_filter` の選択肢が `["なし", "SS", "SSS", "SSS+", "SSS+ABFB", "AP"]` となっており、未クリア（未SSまたは未プレイ）の楽曲のみを抽出する選択肢が存在しない。
- **影響**:
  「まだSSすら取れていない曲から適正な練習曲を探したい」というユーザーニーズに対応できない。

### 【問題点 6】PROJECT.md のファイル名表記と実態の不一致
- `PROJECT.md` 69行目・72行目に `src/models/schema.py`, `src/visualizer/plotter.py` と記載されているが、実在するファイルは `src/database/models.py`, `src/visualizer/visualizer.py` である。

## 5. 修正戦略と実装提案

### 5.1 【戦略 1】ユーザー10605の総合OPI表示・算出に関する戦略
**提案内容**:
1. **仕様の明文化**: `OPI要件定義書.md` に「全曲ログ最尤推定値（1426.7）」と「上位ベスト枠推定値（2021.1）」の差異を追記（非破壊更新）。
2. **UIでの二重表示またはオプション提供**:
   `app.py` または `OPICalculator` において、全曲全ログによる推定に加え、「各定数帯の上位達成状況（または最高スコア群）に基づくアクティブ地力推定」を選択・併記できる仕組み（例: トグルで「全曲推定」と「上位枠推定」を切り替え）を設ける。
   または、シードデータの初期ユーザー10605に対して、ハイレベルスコアログをデフォルト投入しておく。

### 5.2 【戦略 2】レーティング帯域分類バグの修正
**対象ファイル**: `src/visualizer/visualizer.py` (33〜42行目)
**修正提案コード**:
```python
# before:
def get_band_label(rating):
    center = round((rating + 0.25) * 2 - 0.5) / 2
    if center < 18.0:
        return None
    return f"{center:.1f}"

# after:
import math

def get_band_label(rating):
    if rating < 17.75:
        return None
    band_idx = math.floor((rating - 17.75) / 0.5)
    center = 18.0 + band_idx * 0.5
    return f"{center:.1f}"
```
あわせて、`tests/test_tier2_boundaries.py` のテストを `vis.get_band_label`（またはメソッド化）を直接呼ぶ形式に更新する。

### 5.3 【戦略 3】分布統計テーブルの算出とWebUIへの追加
**対象ファイル**: `src/visualizer/visualizer.py`, `app.py`
**修正提案**:

### 5.4 【戦略 4】目標ランク別オフセットの一元定数化
**対象ファイル**: `src/analyzer/opi_calculator.py`, `seed.py`
