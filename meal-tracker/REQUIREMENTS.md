# 個人用食事記録アプリ 要件定義書

状態：v1.1・開発前確認への回答反映済み。今回は要件・仕様作成段階とし、アプリ実装・外部サービス契約・公開は開始しない。

確定した追加条件：クラウド保存＋CSV/JSON出力＋Obsidianへの自動取り込み、本人専用ログイン、写真の履歴保存。iPhoneで1日3〜5回の新規解析。Gemini無料APIでアプリ内解析し、データ利用条件を許容、上限到達時は手入力。ChatGPT・Geminiを既に利用しているが、追加料金は無料を優先する。

## 1. 目的と確定要望

広告に邪魔されず、スマートフォンから手軽に食事を記録し、記録をアプリ外にも蓄積して自分で利用できるようにする。個人利用を対象とする。

- 食事写真・メニュー名・メニュー表からAIで栄養を推定する。
- カロリー、タンパク質（P）、脂質（F）、炭水化物（C）、食塩相当量に加え、Cの内訳として糖質・食物繊維を表示する。
- よく食べるものを一覧化し、ボタン一つで食事に追加できる。
- Notionを参考に、余白・文字・細い罫線を主体とした簡潔な画面にする。
- 開発前に要件定義書と仕様書を作成し、重要な未決事項を確認する。

## 2. 初版の機能要件（提案）

| ID | 要件 | 完了条件 |
|---|---|---|
| R01 | 写真・文字入力 | カメラ撮影、写真選択、メニュー名入力ができ、写真に量や店名を補足できる |
| R02 | メニュー表入力 | 表から候補を抽出し、実際に食べた料理と量を選べる。掲載料理全体を食事に自動加算しない |
| R03 | AI解析・確認 | 料理ごとの推定値・分量・根拠区分を表示し、修正してから保存できる |
| R04 | 栄養サマリー | 料理・食事・日別にkcal、P/F/C、食塩相当量、糖質、食物繊維の計7項目を表示する（kcal以外はg）。糖質・食物繊維はCの内訳として表示する |
| R05 | 食事履歴 | 日付、朝食/昼食/夕食/間食、料理、量を保存し、過去分の追加・編集・削除ができる |
| R06 | よく食べるもの | 確認済み料理や食事セットを定型化し、一覧から1タップで既定量を記録できる。検索・並べ替え・編集・削除ができる |
| R07 | 手動入力 | AIが使えない場合も、料理名と分量・栄養値を直接入力できる |
| R08 | 外部蓄積 | CSV/JSONへ期間指定・全件出力でき、Obsidianへ自動取り込みできる。PC停止中の分は復帰後に同期する |
| R09 | 可搬性・復元 | JSONから食事・定型メニューを復元できる。既存IDの競合を確認し、取り込みで黙って上書きしない |
| R10 | スマホ操作 | 縦画面で主要操作が完結し、ホーム画面追加を考慮する |
| R11 | 本人専用 | クラウド方式では本人だけが履歴・画像を読み書きできる。詳細なログイン方式は保存先選定後に確定 |
| R12 | 推定の識別 | 推定値と入力・表示情報に基づく値を区別し、不明な栄養素を0として扱わない |
| R13 | 目標設定・変更 | カロリーとP/F/Cの1日目標を自分で設定・編集できる。g入力またはカロリーとPFC比率の入力に対応する |
| R14 | 目標履歴 | 変更日前日までは旧目標、変更日から新目標を表示する。過去日への遡及変更は不可。未設定日は未設定とする |
| R15 | 目標の可搬性 | 目標値・適用開始日・変更履歴をCSV/JSON・復元・Obsidian同期に含める |

## 3. 想定する日常の使い方

1. 初めて食べるもの：撮影または名前入力 → 解析 → 内容・量を確認 → 保存。
2. 外食のメニュー表：撮影 → 食べた料理を選択 → 量を確認 → 保存。
3. いつもの食事：「よく食べるもの」の追加ボタン → 今日の食事へ即記録 → 必要なら取り消す。
4. 振り返り：日付を選択 → 日計と各食事を確認 → 修正または出力。

## 4. 精度・データに関する方針

- 数値は測定値であると保証せず、推定の前提（例：ご飯150g、汁を全量摂取）を表示する。
- 食べた量、残した量、ドレッシング・調味料、汁を飲んだかを補足できる。
- 本人が入力した値、パッケージ等から読み取って確認した値、参照できた公式情報、AI推定を区別する。参照先がない場合に出典を捏造しない。
- AIの自己申告だけで「精度95%」などの数値を表示しない。根拠の種類と不足情報を表示する。
- 日計の一部が不明なら「既知分の合計・未入力あり」と表示する。
- 目標カロリーやPFCの自動処方は初版に含めない。既存プロファイルの目標も自動採用しない。

### 目標変更の具体例

以下は動作説明用の架空値であり、栄養目標の推奨ではない。

- 9月21日まで：2,400kcal、P150g・F80g・C270g。
- 9月22日に変更：2,600kcal、P160g・F80g・C310g。
- 9月21日の履歴は旧目標、9月22日以降は新目標を表示。9月22日の朝食を変更前に記録していても、その日全体を新目標で比較する。
- 初期目標を登録する前の日には、新しい目標を埋め戻さない。
- 目標変更で食事の実績値を変更しない。糖質・食物繊維・塩分の目標設定は今回の必須対象外。

## 5. デザインと利用条件（提案）

- 白を基本に濃いグレーの文字、薄い罫線、補助色は控えめにする。広告、ランキング、SNS共有は設けない。
- 「今日」「履歴」「よく食べるもの」を主要導線とし、設定は補助導線にする。
- 最初の画面に当日の栄養サマリーと食事追加ボタンを表示する。
- スマホの片手操作を重視し、主要タップ領域は44px以上、本文16px以上を設計目標とする。
- 読み込み中、未記録、解析失敗、通信断、保存失敗をそれぞれ表示し、入力のやり直しを最小化する。
- 初版はオンライン利用を基本案とする。通信断では送信失敗と未保存状態を明示し、入力を保持する。完全なオフライン記録・同期は別途確定する。

## 6. 開発前に確認する事項

| ID | 確認事項 | 推奨案・判断への影響 | 状態 |
|---|---|---|---|
| Q1 | アプリ外への蓄積方法 | クラウドを正本にし、CSV/JSON出力と保管庫への自動取り込み。PC停止中も記録し、PC復帰後に取り込む | 確定 |
| Q2 | 外部AIへの送信・予算 | 無料APIでアプリ内解析。無料枠のデータ利用条件を許容。上限時は手入力。有料化しない | 確定 |
| Q3 | スマホと写真保存 | iPhone、1日3〜5回の新規解析、本人専用ログイン、写真保存 | 確定 |

写真は本人が削除するまで保存する基本設計とし、無料容量上限では新規画像保存を止めて案内する。勝手な削除や有料化はしない。初版は独立アプリを提案する。既存チャットへの貼り付け案は代替案として記録し、初版の必須機能にはしない。

料金と無料API条件、開発工数の内訳は同フォルダの COST_ESTIMATE.md に記載。AIはGemini API無料枠を採用方針とする。ホスティング・DBの最終選定と実アカウントの無料枠確認は技術着手時の残課題。完全無料・無制限のAI解析を前提にせず、無料枠超過時に自動で有料プランへ移行しない。

## 7. 初版に含めないもの
